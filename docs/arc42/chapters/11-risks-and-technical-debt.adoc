== Risks and Technical Debts

=== Technical Risks

[cols="1,2,2,1"]
|===
|Risk |Impact |Mitigation |Priority

|WebSocket connection failures
|Clients lose real-time updates.
|Heartbeats detect dead connections; clients reconnect and resynchronize everything they show over REST.

|High

|Database performance
|Slow responses during a large tournament.
|Query optimization and indexing.

|Medium

|In-memory settings
|The auto-start flag, the selected printer and print-on-assign are kept in memory and reset when the backend restarts.
|Persist them in a sidecar table when they need to survive a restart.

|Medium

|Dependence on mktt and click-TT
|Tournament data cannot be prepared without the legacy toolchain.
|Document the offline workflow; consider a future import replacement.

|Medium
|===

=== Technical Debt

* Code duplication between the three frontend applications. The shared modules (`update-events`, `result-entry`, `match-state`) are identical copies per application by decision; a change must reach every copy.
* All three frontends are kept on the same major Angular version (currently Angular 21); keeping them in sync requires a coordinated upgrade effort.
* There is no authentication (chapter 8).
* Open follow-ups are tracked in `docs/follow-ups.md`.
