== Building Block View

This chapter describes the building blocks at two C4 levels: the container level (Level 2) and the component level (Level 3).

=== Level 2: Containers

[plantuml, target="container", format="svg"]
----
include::../diagrams/container.puml[]
----

[cols="1,3"]
|===
|Container |Responsibility

|Admin View
|Angular 21 SPA for tournament administration: match assignment, calling, queue management, results.

|Result View
|Angular 21 SPA for displaying live results and standings.

|Table Manager View
|Angular 21 SPA for table-specific match management and result entry.

|Reverse Proxy
|Nginx. Serves the three SPA bundles and proxies API and WebSocket traffic to the backend.

|Backend
|Kotlin 2.3 on Spring Boot 4.1, a modular monolith structured with Spring Modulith. REST API, WebSocket broadcasting and PDF generation.

|Tournament Database
|MariaDB/MySQL in production, H2 in tests. Persists players, matches, tables, groups and settings.
|===

=== Level 3: Backend Modules

The backend is a modular monolith. Each top-level package under `de.ttt.management` is a Spring Modulith module and follows an onion architecture (`domain` → `application` → `infrastructure`).

[plantuml, target="backend-components", format="svg"]
----
include::../diagrams/backend-components.puml[]
----

[cols="1,3"]
|===
|Module |Responsibility

|registration
|Players, clubs, doubles, disciplines and registration state (paid/active/seed). Register/unregister players.

|grouping
|Group formation, seeding and knockout placement. Currently scaffolded, not yet implemented.

|tournament
|Match lifecycle and state machine, Queue/MatchList, table assignment, results, caller (first/second/third call) and table-manager operations.

|settings
|System settings and printing (referee sheets, certificates).

|outbound
|The single WebSocket publisher. Consumes domain events and pushes updates to connected clients.

|Shared configuration
|`OpenApiConfig` and other cross-cutting Spring configuration in the root package.
|===

Each module internally layers as follows:

[cols="1,3"]
|===
|Layer |Responsibility

|domain
|Aggregates, value objects, match-state enum and repository ports (interfaces only).

|application
|Use-case orchestration, application services, event publication.

|infrastructure.database
|JdbcClient repository adapters (plain SQL, no JPA/Hibernate).

|infrastructure.web
|REST controllers.

|infrastructure.messaging
|Event listeners/publishers.
|===
